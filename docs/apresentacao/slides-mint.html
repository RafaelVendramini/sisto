Diferencial

Segurança e LGPD desde a primeira linha

🛡️

Cada perfil vê só o que precisa

  • 5 perfis, regra garantida pela API, não só pela tela
  • Professor vê as que registrou; tutor, as dos tutorados
  • Dados reduzidos para quem não é Gestão
📜

Tudo fica registrado

  • Histórico de cada ocorrência: quem, o quê e quando
  • Auditoria de cadastros, senhas e encerramentos
  • Nada é apagado; ocorrência encerrada não reabre
🔐

Acesso protegido

  • Senhas com hash (bcrypt) e sessão de até 8 h
  • Bloqueio corta o acesso na hora
  • 5 tentativas erradas em 15 min → espera
  • Troca de senha encerra todas as sessões
🏫

Dados de menores tratados com cuidado

  • Banco hospedado no Brasil (São Paulo)
  • Só dados fictícios até a autorização da escola
  • Fora dos buscadores; política de privacidade (a validar com a escola)
350testes de ponta a ponta

Contra um banco real, incluindo a matriz de permissões inteira: cada perfil, em cada rota, recebe exatamente o que pode — e é recusado no resto.

IA: metodologia de uso

Uma equipe de agentes de IA, com o Dev no comando

Dev + Tech Leaddecide e aprova
→
AnalistaSSD → Issues
→
Dev backAPI e banco
→
Dev fronttelas React
→
QAtestes
→
Revisorsegurança e LGPD

✔ Benefícios

  • Velocidade: agentes em paralelo, uma Issue cada
  • Qualidade: todo código chega com testes e revisão
  • Rastreabilidade: cada entrega ligada a RF, RN e Issue
  • Documentação viva: SSD atualizado a cada Sprint

⚠ Problemas e como resolvemos

  • Inventar requisito → o SSD é a única fonte de verdade
  • Conflitos entre agentes → uma branch por Issue
  • Limite de uso da IA → trabalho em lotes menores
  • Risco com segredos → regra que bloqueia a IA de ler o .env; só dados fictícios

Regra de ouro (protocolo AIP): a IA propõe, o Dev decide — nenhum commit, PR ou merge sem aprovação humana.
